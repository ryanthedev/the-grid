# Agent journal: using this Mac through theGrid

One line per task: what I tried, where a tool fell short, what I changed.

- Finder: tree usable after row flattening (171→74 nodes). AXPress on disclosure triangles is listed but refused (-25205); a Double 1.0 AXValue is accepted and ignored; rows refuse AXScrollToVisible. Added: row lines, includeOffscreen, ui.select, ui.scrollTo (+scrollbar fallback), numeric setValue (ints), press fallback to AXDisclosing. Lesson: never press unlabeled/disabled buttons to 'see what happens' (I did once; harmless).
- System Settings: sidebar navigation by ui.select and pane navigation by ui.press work with no focus or pointer; read 3 switch states + combo value exactly. Friction: switches/combos are unlabeled (label is a sibling text) -> add label inference; zero-height separator rows are noise -> drop.
- Cross-display: region clips to one display and reports the true frame; 2x scale right. Gap: result does not say the request was clipped -> add clipped/requested.
- Finder, round 2: AXPress on a disclosure triangle returns error -25205 AND expands the folder. My first "fallback" then toggled it back (net nothing). Lesson, now the rule in ui.press: judge an action by its effect, not its return code.
- Same-app focus theft: the leak is one chunk per interrupted call, so the chunk IS the leak. Guarded typing now uses 5-character chunks (was 20): measured 5 leaked of 70 posted under a thief every 120 ms; 0 to another app.
- Chrome ignores a single cmd+q when "Warn Before Quitting" is on. A region capture shows the screen (whatever is on top), not a particular window.
- Skipped on purpose: layout stress on the upper display's space and any click there — a fight was playing fullscreen on it.
- ui.query: 92 bytes to find one row in System Settings vs 3,562 for the snapshot. Snapshot once to learn an app; query after that.
- expect*: the effect is the verdict. A wrong expectation told me what the title actually was, which is how I learned System Settings' General pane has an empty window title. Expectations read the live AX title; the server's cached title lags by ~1.5 s.
- Finder remembers a folder's disclosure state across windows and a press toggles: read the triangle's value before pressing.
- Menu bar: the whole index reads without opening a menu (Finder: 182 commands in 40 ms). The trap is state, not reading: a background app reports its document commands disabled (no key window), and AXPress on a disabled menu item answers success and does nothing. So menu.invoke brings the app (or the named window) forward, re-reads enabled, and only then presses or refuses. Prototyping the AX calls in a scratch `swiftc` harness against the real file let me settle all of this before spending the one deploy.
- Spaces: reading is easy and exact (SkyLight lists displays, spaces, types, windows). Writing is where macOS 26.2 says no: five ways of moving my own fixture window from space 3 to the hidden space 4 (the server's SLSMoveWindowsToManagedSpace, the compat-ID workaround, Add/Remove, AddWindowsAndRemoveFromSpaces, from the server and from a harness) all returned normally and left it on 3. The server log agrees: every space move it ever confirmed was between two displays' visible spaces. So window.pull and space.switch read the result back and fail loudly, and refuse anything touching a fullscreen space before trying. Not run live: space.switch (a video was playing; the owner's call) and the pull happy path (no way to stage a window on a hidden space without switching).
- Clipboard: the tool is twenty lines; the care is all around it. It lives in the server because the pasteboard belongs to the GUI session and `thegrid mcp serve` may not be in one. Reads refuse concealed/transient markers (decided from the type list alone, a pure function), cap at 64 KB on a character boundary, and return the change count, which turns "did cmd+c work?" into a comparison. Testing a clipboard means borrowing the user's: a helper process holds every item and type in memory (never on disk), restores on command or when its stdin closes, and verifies by reading back; I proved it on a private named pasteboard before letting it near the real one. Unit tests use NSPasteboard.withUniqueName() and never the general pasteboard.
